# HACK:ON

누구나 5분 만에 해커톤을 연다. 회사는 협찬하고, **끝난 뒤 2주까지** 성과를 받는다.

라켓온(RACKET:ON)의 뼈대를 그대로 가져왔다 — 단일 HTML 화면 + 단일 파일 서버 + `--test` 자체 점검.
새로 짠 것은 도메인뿐이다. 자세한 재활용 목록은 [PLAN.md](PLAN.md) §4.

| 찾는 것 | 파일 |
|---|---|
| **어떻게 키울 것인가 · 협찬 받는 순서** | [PLAN.md](PLAN.md) |
| **대회를 실제로 어떻게 여나** | [GUIDE.md](GUIDE.md) |
| 화면 | `hack-on.html` |
| 윈도우 실행기 | `desktop.js` · `HACKON.bat` · `HACKON.vbs` |
| 서버 | `server.js` |

## 세 가지 방식으로 쓴다

하나의 코드로 셋을 만든다. 따로 만들지 않는다.

| 무엇 | 어떻게 | 비고 |
|---|---|---|
| **웹앱** | `npm start` → http://localhost:8788 | 링크만 주면 설치 없이 참여 |
| **윈도우 프로그램** | `HACKON.bat` 더블클릭 (콘솔까지 없애려면 `HACKON.vbs`) | 주소창 없는 앱 창으로 뜬다. 창을 닫으면 서버도 꺼진다 |
| **휴대폰 앱** | 브라우저에서 “홈 화면에 추가” | PWA. 아이콘이 생기고 전체 화면으로 뜬다 |

## 실행

```bash
npm start        # 서버 + 화면 → http://localhost:8788
npm test         # 자체 점검 29가지 (함수만 본다)
npm run check:e2e   # 완주 테스트 26단계 (브라우저로 처음부터 끝까지)
```

`check:e2e` 는 **빈 DB 와 임시 포트로 서버를 스스로 띄운다.** 켜 둔 서버와 `data/hackon.db` 는
건드리지 않는다 — 검사가 개발용 DB 위에서 돌면 몇 번째 실행이냐에 따라 결과가 달라지기 때문이다.
대회 개설 → 참가 → 제출 → 심사 → 협찬사 → 성과 → 공개 링크 → 데모 모드까지를 브라우저로 한 번에 지나간다.

Node 22 이상. **설치할 패키지가 없다** — DB(`node:sqlite`)와 HTTP(`node:http`) 모두 Node 안에 있다.

`hack-on.html` 을 그냥 더블클릭하면 서버 없이 예시 데이터로 화면만 볼 수 있다.
라켓온과 같은 두 갈래이고, `LIVE = location.protocol.startsWith('http')` 한 줄로 갈린다.

## 무엇이 되나

- **제출 마감** — 남은 시간이 1초마다 줄어들고 1시간을 끊으면 색이 바뀐다.
  마감이 지나면 **서버가** 제출을 막는다. 인터넷이 터지면 진행자가 30분씩 미룬다
- **대회 상태** — 모집중·진행 중·끝남을 날짜에서 바로 계산해 목록과 공개 페이지에 붙인다
- **심사 진행 현황** — 심사위원이 몇 명이고 전원이 다 본 팀이 몇 팀인지.
  팀 화면에서는 누가 봤고 누가 안 봤는지 이름으로 나온다
- **대회 열기** — 이름·날짜만 넣으면 끝. 심사 기준은 기본값(독창성30·완성도30·실용성25·전달력15)
- **참가 신청** — 팀 이름·연락처·역할·혼자 왔는지·**어디서 보셨나**·하고 싶은 것.
  공개 링크에서도 바로 신청된다 — 모집 글에 그 주소를 쓴다.
  정원과 중복 이름은 서버가 막는다
- **개인정보 동의** — 항목·목적·보유기간(6개월)을 화면에 적고 동의를 받는다.
  동의 없이는 **서버가** 신청을 안 받는다. 동의한 시각을 남긴다 — 증거는 그것뿐이다.
  촬영·사진 공개는 따로 받고, 비동의 팀은 등록 데스크에 표시된다
- **등록 데스크** — 당일 아침에 이 칸만 보면 된다. 온 팀을 누르고, 잘못 눌렀으면 다시 누른다
- **어디서 왔나** — 유입 경로별 집계. 2회차 홍보를 어디에 할지 이 표가 정한다
- **제출·심사** — 순위에서 팀을 누르면 열린다. 참가팀은 링크·설명을 내고,
  심사위원은 이름과 항목별 점수를 넣는다. 같은 이름으로 다시 넣으면 고쳐진다.
  순위는 항목 가중 평균이라 심사위원 수가 달라도 흔들리지 않는다
- **심사위원 링크** — `/j/<대회id>`. 로그인 없이 점수만 넣는다.
  **다른 팀 점수와 순위는 서버가 아예 안 준다** — 심사 중에 순위를 보면 점수가 끌려간다.
  아직 안 본 팀이 위로 온다
- **공개 링크** — `/e/<대회id>` 를 그대로 보내면 로그인 없이 열린다.
  협찬사·성과·순위·제출작이 한 장에 나오고 편집 칸은 없다
- **협찬사 등록** — 넣은 곳이 공개 페이지 ‘함께한 곳’에 그대로 뜬다
- **명단 내려받기** — 순위 화면에서 참가팀·연락처·제출 링크를 엑셀로 뽑는다.
  행사 당일 종이로 들고 갈 것이다
- **사후 지원** — 끝나고 팀을 봐 줄 사람을 **행사 전에** 정해 짝지어 둔다.
  기한은 기본이 대회 끝나고 14일이고, 넘기면 빨갛게 뜬다.
  공개 페이지에 “이 팀은 누가 언제까지 봐 드립니다”가 나온다 —
  참가자에게는 약속이고 협찬사에게는 증거다
- **결과 보고서** — `/e/<대회id>/report`. 개요·유입 경로·협찬사·성과 네 숫자·
  사후 지원 이행·제출작·다음 회차 제안이 한 장에. 인쇄하면 그대로 PDF 다.
  손으로 쓰던 것을 앱이 채운다
- **협찬 성과** — 완주율·면접 연결·도입 검토·채용을 기록한다.
  “몇 명이 봤다”를 쓰지 않는 것이 이 서비스의 차별점이다

## 윈도우 프로그램은 어떻게 만들었나

일렉트론을 쓰지 않았다. 창 하나 얻으려고 200MB 를 같이 배포할 이유가 없다.
대신 윈도우에 이미 깔려 있는 엣지·크롬의 `--app` 모드를 쓴다.
주소창도 탭도 없는 창이 뜨고, 프로필 폴더를 따로 줘서 쓰던 브라우저 창과 섞이지 않는다.

`desktop.js` 가 하는 일은 넷이다.
빈 포트를 잡고 → 서버를 띄우고 → 뜰 때까지 기다렸다가 → 앱 창을 연다.
**그 창을 닫으면 서버도 같이 내려간다.** 노드 프로세스가 남지 않는다.

```bash
node desktop.js --check   # 띄우지 않고 브라우저·포트·화면 파일만 확인
```

## 왜 성과를 따로 세나

해커톤을 후원한 회사가 가장 답답해하는 것은 **성과를 숫자로 증명하지 못하는 것**이다.
그리고 대회 결과물의 대부분이 행사 직후 버려진다.
그래서 이 서비스는 행사 자체보다 **끝난 뒤 2주**를 제품으로 본다.
`outcomes` 표가 그 2주를 담는 자리다.
