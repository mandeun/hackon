## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
«형이 참여한 프로젝트» 를 보여 달라는 요청(루키팀 방, 9/29)에 대한 태스크다.

`/p/<id>` 에는 이미 많은 것이 있다: 티어, 만든 것(열림·며칠째), 기록증, 도전장, README 뱃지, 기여 XP, 완주·완주율·안 온 횟수, 실력·매너 평가, 나온 대회. **빠진 건 둘이다.**

**1. 올린 강의 (TASK-25 표를 읽기만 한다)**
- 강의가 있으면 프로필에 «올린 강의 N» 카드를 붙인다.
- 스스로 고른 등급 LEVELS 가 «가르칠 수 있음» 인 사람에게 강의가 있으면 옆에 «강의 N개로 확인» 을 붙인다.
  - 지금은 스스로 고른 값일 뿐이라 근거가 없다. 강의가 그 근거가 된다.
- xpOf 에 «강의 올림» 항목을 더한다.

**2. 밖에서 만든 것**
- 해커톤 밖의 결과물을 적는 칸이다. 예: 진로 사이트, 가짜연구소 프로젝트.
- 표 `outside`: person, title, url, role, at, ok(운영자 확인)
- 본인은 팀 열쇠(x-tkey)로 올린다. 프로필 고치기와 같은 본인 확인 길이다.
- **운영자가 확인하기 전에는 본인에게만 보인다.**

**티어·실력·매너는 건드리지 않는다**
- 티어는 완주·수상·동료 실력으로만 오른다(rankOf).
- 강의나 밖에서 만든 것이 티어를 올리면, 스스로 올린 주장이 대회 기록과 섞인다. 티어 카드 아래 적힌 «숫자는 대회 기록에서만 나옵니다» 가 거짓말이 된다.
- 매너는 1~5 점 동료 평가와 «안 온 횟수» 로 이미 따로 센다. 당근식 «매너 온도» 로 바꾸지 않는다.

**보안**
- 밖에서 만든 것의 주소는 webUrl() 검사를 통과해야 공개된다. `javascript:` 나 `data:` 는 거른다.
- 운영자 확인(ok=1) 전에는 GET /api/people/:id 응답에 싣지 않는다. 쇼케이스 공개 문 셋과 같은 원칙이다.
- 링크에는 `rel="noopener noreferrer"` 를 단다.
- 새 공개 쓰기 길이므로 WRITE_LIMIT 을 건다.
- 강사가 팀 신청 이력이 없으면 팀 열쇠가 없다. 그런 사람은 siteAdmin 이 사람을 만들고 이어 준다. 본인 주장만으로 남의 people.id 에 붙지 못하게 한다.
