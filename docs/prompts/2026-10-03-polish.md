# 작업 프롬프트 — 2026-10-03 «다듬기»

> 사용자 요청: 만든 기능을 발전시킨다. 레드팀 공격, 뉴스를 5살도 알아듣게, «오늘 새로 생긴 것» 보다 «한 주간 하트가 확 는 것»,
> 모든 기능의 사용성과 필요 없는 것 검토, 사용자 친화 설계, 더 붙일 것을 여러 각도로. 프롬프트는 에이전트가 직접 쓰고 그대로 따른다.

## 역할
너는 HACK:ON 의 제품 담당이자 공격자다. 기능을 늘리지 말고 **줄이고, 쉽게 하고, 뚫리는 곳을 막는다.**

## 순서(하나 끝낼 때마다 커밋)
1. **레드팀** — 이번 달 새로 만든 공개 길(팀원 추천·좋아요·소개 세 칸·기여자 장부·한꺼번에 치우기·연습용·추천 코드·브리핑·지갑·/partner·/biz·/cert·/en)을
   «어떻게 뚫나» 로 본다: 남의 열쇠 없이 쓰기, 연락처 새기, 도배, 숫자 부풀리기, 화면 주입(XSS), 남의 이름 사칭.
   찾은 것은 고치고, 고친 것마다 단언을 쓰고 망가뜨려 빨간 줄을 본다. 못 고친 것은 이유를 적는다.
2. **뉴스 «이번 주 확 뜬 것»** — 수집할 때마다 별·하트 수를 날짜별로 적어 두고, 7일 동안 는 만큼(gain)으로 줄 세운다.
   처음 본 지 7일이 안 된 것은 처음 본 날 수에서 는 만큼. 숫자가 없는 출처는 이 판에 안 낀다(모름은 0 이 아니다).
3. **5살 설명** — 줄마다 «쉽게:» 한 줄. 출처 종류(모델·논문·앱·데이터·저장소·할인·기사)별 기본 문장 + 제목 속 어려운 말(LLM·에이전트·RAG·MCP 등)을 쉬운 말로.
   AI 를 부르지 않는다(비용 0, 틀린 말 지어내지 않기). 모르는 말은 설명하지 않는다.
4. **사용성 검토** — 화면마다 «처음 온 사람이 5초 안에 무엇을 누르나» 하나로 본다. 겹치는 안내 페이지는 한 곳으로 모은다,
   첫 화면 고리는 더 줄인다. 지우는 것은 «고리에서 빼기» 까지만 — 주소는 살려 둔다(밖에 뿌린 링크가 죽지 않게).
   검토 결과는 `docs/usability.md` 에 표로.
5. **더 붙일 것** — 사용자·운영자·협찬사·기관·해외·돈 여섯 각도로 짧게. 만들지 말고 순서만.
