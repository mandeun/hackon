# 구조

서버는 `server.js` 파일 하나, 화면은 `hack-on.html` 파일 하나, DB 는 SQLite 파일 하나입니다.
이 문서는 그 안에 무엇이 들어 있는지 적은 것입니다.
표 이름과 칸 이름은 `server.js` 의 `CREATE TABLE` 에서 그대로 옮겼습니다.

## 표

### 대회와 사람

| 표 | 무엇을 담나 |
|---|---|
| `events` | 대회 한 줄. 제목·여는 사람·날짜·마감·상금·정원·진행 순서·심사 기준표·열쇠 |
| `owners` | 주최자. `id` 가 곧 주최자 열쇠입니다. `kakao` 가 비면 열쇠만 쓰는 사람 |
| `meta` | 서버가 쓰는 값 한 쌍씩 |
| `teams` | 참가팀. 이름·연락처·역할·동의 시각·체크인·자리 번호·팀 열쇠 |
| `people` | 사람. 연락처를 해시로 바꾼 것이 `id` 입니다. 연락처 원문은 들어오지 않습니다 |

### 제출과 심사

| 표 | 무엇을 담나 |
|---|---|
| `submissions` | 팀당 하나. 링크·설명·AI 를 쓴 단계·AI 제안 중 버린 것·쇼케이스 동의 |
| `scores` | 심사위원이 넣은 항목별 점수 |
| `reviews` | 심사평. 좋았던 점(`good`)과 더 하면 좋을 것(`next`) |
| `votes` | 관객 평가와 참가자 상호평가. 한 사람이 한 팀에 한 번, 1~5점 |
| `verdicts` | 주제를 올린 사람의 판정. 「이거면 됩니다」인지 아닌지 |

`scores` 와 `votes` 는 따로 둡니다. 심사 점수와 관객 표가 섞이지 않게 하려는 것입니다.

### 구하기와 후원

| 표 | 무엇을 담나 |
|---|---|
| `needs` | 빈자리 판. 운영자가 올린 필요한 자리 |
| `pledges` | 그 자리를 맡겠다고 신청한 사람. `contact` 는 운영자만 봅니다 |
| `offers` | 자리 밖 제안. 운영자가 안 올린 역할을 「제가 할 수 있어요」로 보냅니다 |
| `requests` | 받는 사람. 후원자·의뢰자가 올린 주제와 문제 |
| `leads` | 연락해 본 곳. 장소·심사위원·강사·스태프·멘토·협찬 |
| `sponsors` | 협찬사. 금액·로고·링크·증빙·지킨 약속 |

### 행사가 끝난 뒤

| 표 | 무엇을 담나 |
|---|---|
| `supporters` | 끝난 뒤 팀을 봐 주기로 한 사람들 |
| `assignments` | 어느 팀을 누가 언제까지. 기한 없는 약속은 인사말이라 `due` 가 있습니다 |
| `checks` | 2·6·12주에 팀에게 물어본 것 |
| `followups` | 2주 뒤 도구 확인. 팀당 한 칸 |
| `outcomes` | 협찬 성과. 면접·도입검토·채용·후속미팅 |
| `surveys` | 끝난 뒤 설문 세 문항. 팀당 하나 |

### 평판과 소통

| 표 | 무엇을 담나 |
|---|---|
| `ratings` | 사람이 사람을 평가. 실력과 매너를 따로 받습니다 |
| `event_ratings` | 참가자가 대회를 평가. 주최자 평판이 여기서 나옵니다 |
| `questions` | 대회 안 묻고 답하기. 팀 열쇠로 묻고 운영자가 답합니다 |
| `notices` | 지난 소식. 공개 페이지가 시각과 함께 보여 줍니다 |
| `feedback` | 앱 피드백 |
| `push_tokens` | 아이폰 앱의 푸시 토큰. 발송 열쇠가 없으면 저장만 합니다 |

표를 늘리거나 줄였을 때는 `grep 'CREATE TABLE' server.js` 로 목록을 다시 맞춥니다.

## 화면 주소

`/` 만 `home.html` 을 받고, 나머지 화면은 모두 `hack-on.html` 을 받습니다.
화면 파일이 `location.pathname` 을 읽고 갈라집니다. 서버에 화면을 여러 벌 두지 않습니다.

| 주소 | 화면 | 열쇠 |
|---|---|---|
| `/` | 첫 화면. 소개와 열린 대회 목록 | 없음 |
| `/app` | 운영 화면. 대회를 열고 굴립니다 | 운영 또는 주최자 |
| `/e/<대회id>` | 공개 페이지. 참가 신청도 여기서 받습니다 | 없음. `?t=` 로 팀 열쇠를 실을 수 있습니다 |
| `/e/<대회id>/report` | 결과 보고서. 인쇄하면 PDF 입니다 | 없음 |
| `/j/<대회id>` | 심사 화면 | 심사 열쇠 (`?k=`) |
| `/v/<대회id>` | 관객 평가 · 상호평가 | 투표 열쇠 (`?k=`) 또는 팀 열쇠 |
| `/tv/<대회id>` | 현장 큰 화면. 10초마다 스스로 다시 받습니다 | 없음 |
| `/p/<사람id>` | 사람 프로필. `id` 는 열두 자리 16진수입니다 | 없음 |
| `/give` | 줄 수 있는 것. 자리 맡기와 제안 | 없음 |
| `/ask` | 받는 사람. 주제와 문제를 올립니다 | 없음 |
| `/r/<요청id>` | 올린 주제의 상태와 판정 | 받는 사람 열쇠 (`?k=`) |
| `/s/<ref>` | 준 사람의 화면. `ref` 는 `p` 나 `o` 에 번호를 붙인 것입니다 | 후원 열쇠 (`?k=`) |
| `/manual` | 운영 매뉴얼. `GUIDE.md` 를 읽어 화면으로 만듭니다 | 없음 |
| `/privacy` | 개인정보 처리방침 | 없음 |

API 는 전부 `/api/` 아래에 있습니다. 길 목록은 `server.js` 의 `routes(db)` 한 곳에 있습니다.

## 로그인

로그인은 선택입니다. 열쇠 하나가 곧 계정이고, 로그인은 «그 열쇠를 여러 기기에서 꺼내는 길»입니다.

| 공급자 | 환경변수 | 내보내는 곳 | 회원번호 | 이메일을 믿는 조건 |
|---|---|---|---|---|
| 카카오 | `KAKAO_KEY`(+`KAKAO_SECRET`) | `kauth.kakao.com` | `id` | `is_email_valid && is_email_verified` |
| 구글 | `GOOGLE_KEY`·`GOOGLE_SECRET` | `accounts.google.com` | `sub` | `email_verified` |
| 네이버 | `NAVER_KEY`·`NAVER_SECRET` | `nid.naver.com` | `id`(앱마다 다름) | `@naver.com` 인 것만 |

표는 `server.js` 의 `LOGINS` 한 곳입니다. 키를 안 주면 `/auth/<이름>` 은 **404** — 없는 주소입니다.
화면은 `/api/auth` 의 `providers` 만 보고 단추를 그립니다. 화면에 목록을 적지 않습니다.

켜려면 그쪽 콘솔에 **돌아올 주소**를 등록하고 키를 환경변수로 줍니다.
돌아올 주소는 도메인마다 하나씩(`SITES` 에 적힌 주소 × `/auth/<이름>/done`).

### 같은 사람 알아보기

한 사람이 카카오로도 구글로도 들어옵니다. 계정이 갈리면 지난 대회가 안 보이고,
잘못 합치면 남의 계정이 넘어갑니다. 근거는 넷이고 센 것부터 씁니다 — `loginAs()`.

| 순서 | 근거 | `how` |
|---|---|---|
| ① | 공급자+회원번호가 이미 있다 | `known` |
| ② | 로그인한 채로 «다른 로그인도 붙이기»를 눌렀다 | `linked` |
| ③ | 믿을 수 있는 이메일이 기존 로그인과 같다 | `email` |
| ④ | 이 브라우저가 든 주최자 열쇠 | `key` |
| — | 그래도 없으면 새 계정 | `new` |

- ③④가 다른 계정을 가리키면 `mergeOwners()` 로 **합칩니다**(`events`·`event_trash`·`news`·`logins`).
  단, 열쇠 쪽에 이미 로그인이 붙어 있으면 남의 계정일 수 있으니 손대지 않습니다.
- 이메일은 원문을 남기지 않습니다. 서버 서명 열쇠로 HMAC 한 값(`logins.ehash`)만 둡니다.
  못 믿는 이메일은 값을 아예 만들지 않습니다 — 여기가 느슨하면 남의 주소를 적어 둔 사람이
  그 계정을 가져갑니다.
- `state` 는 쿠키(`hackon_st`)와 대조합니다. 없으면 공격자가 자기 `code` 링크를 보내
  피해자 브라우저를 자기 계정에 묶습니다.

| 표 | 무엇 |
|---|---|
| `logins(provider, uid, owner, ehash, nick)` | 로그인 한 줄 = 공급자 하나. 주인은 하나 |
| `owners.kakao` | 옛 자리. 켤 때 `logins` 로 옮겨심고 읽지 않습니다 |

## 역할과 열쇠

역할은 열쇠가 정합니다. 로그인해도 «주최자 열쇠를 가진 것»과 같습니다.

| 역할 | 열쇠 | 판정 함수 |
|---|---|---|
| 운영자 | `events.okey` 또는 `owners.id` | `isAdmin()` |
| 심사위원 | `events.jkey`. 운영자도 포함됩니다 | `canJudge()` |
| 투표자 | `events.vkey`, 상호평가면 `teams.tkey` | `canVote()` |
| 참가팀 | `teams.tkey` | `peerTeam()` |
| 받는 사람 | `requests.rkey` | `canReceive()` |
| 준 사람 | `pledges.pkey` · `offers.pkey` | `giveView()` |

`events.okey` 가 빈 대회는 열쇠가 생기기 전에 만들어진 것이라 그대로 열립니다.
새로 만드는 대회에는 언제나 열쇠가 붙습니다. 빈 열쇠를 남기면 「비면 아무나」라는 구멍이 생깁니다.

열쇠를 잃었을 때 되찾는 길은 [SECURITY.md](../SECURITY.md) 에 적었습니다.

## 마감 전에는 결과물과 점수를 내보내지 않습니다

`closed(e)` 가 기준선입니다. `events.due` 가 있으면 그 시각, 없으면 `events.ends` 날짜로 갈립니다.
마감 전에 **운영자가 아닌** 사람이 대회를 읽으면 서버가 응답에서 이것들을 지웁니다.

| 지우는 것 | 어디서 | 왜 |
|---|---|---|
| 제출 링크 (`url`) | `board()` · `follow()` · `judgeView()` | 먼저 낸 팀의 결과물을 뒤에 내는 팀이 보고 만듭니다 |
| 점수·순위·표 (`score` `rscore` `rank` `vote` `votes`) | `board()` | 심사 중에 순위가 보이면 심사위원이 그것에 맞춥니다 |
| 한 줄 평 (`words_public`) | `board()` | 마감 뒤에만 나갑니다. 누가 썼는지는 담지 않습니다 |
| 순위 다섯 줄 (`ranks`) | `tv()` | 마감이 지나고 심사가 시작된 뒤에만 벽에 띄웁니다 |
| 자리 번호 목록 (`seats`) | `tv()` | 마감 뒤에 붙입니다 |

심사 열쇠만 가진 심사위원도 마감 전에는 제출 링크를 못 봅니다.
심사 주소는 열쇠 없이도 대회 id 만 알면 화면이 열리기 때문에, 그 자리를 경쟁 팀이 쓰는 길을 막은 것입니다.
심사는 마감 뒤에 하므로 그때 링크가 열립니다.

제출 링크를 지울 때 `hidden` 칸을 대신 붙입니다. 무엇을 만들고 있는지는 서로 보이고,
결과물만 마감까지 잠깁니다. 제목과 설명은 마감 전에도 보입니다.

현장 큰 화면(`tv()`)은 제출 링크와 연락처를 아예 담지 않습니다. 벽에 걸어 두는 화면이라
열쇠를 두지 않았고, 대신 내보낼 것을 처음부터 줄였습니다.

연락처와 유입 경로와 동의 기록은 **마감과 관계없이** 운영자가 아닌 사람에게 나가지 않습니다.
화면에서 감추는 방식을 쓰지 않습니다. 화면에서 감추면 브라우저 콘솔에서 보이기 때문입니다.

## 모름을 0 으로 그리지 않습니다

값이 없는 것과 0 인 것은 다릅니다. 이 서비스는 상태를 **있음·없음·모름** 셋으로 다룹니다.

- `events.judged` 는 `''` 모름, `'no'` 못 구함, `'yes:n'` 구함 셋입니다. 모름을 0 으로 그리지 않습니다.
- `events.budget` 은 안 준 것과 0원을 준 것을 갈라 둡니다. 0원을 주면 온라인 대회가 됩니다.
- `requests.followup` 은 `''` 이면 모름입니다. 2주 뒤 답이 없는 것을 「안 씀」으로 세지 않습니다.
- `submissions.show` 는 0 에서 시작합니다. 쇼케이스 동의는 본인이 켜야 생깁니다.
  옛 배포판의 빈칸을 동의로 읽지 않습니다.
- 설문 요약은 응답이 세 건 미만이면 숫자를 내지 않습니다.
  두 팀의 평균은 어느 팀이 몇 점인지 드러냅니다.
- 심사위원별 등수 보정에서 한 팀만 본 심사위원은 그 팀에 100 을 줍니다.
  비교할 것이 없어 모름인데 0 으로 그리면 벌이 됩니다.
  두 팀만 본 심사위원은 보정에서 뺍니다.

## 백업

서버가 10분마다 DB 를 통째로 `data/backup/` 에 복사하고 최근 열두 벌을 남깁니다.
운영 화면의 「통째로 내려받기」로 지금 상태를 JSON 파일 하나로 받을 수 있습니다.
대회·팀·제출·점수·심사평·협찬사·성과·지원자·배정이 들어가고 열쇠는 담기지 않습니다.

대회를 지우면 지우기 직전 사본이 파일로 남습니다. 그 사본과 주최자 열쇠가 있으면
`/api/events/restore` 로 되살릴 수 있습니다. 사본에 연락처가 들어 있어 운영자만 보관합니다.
